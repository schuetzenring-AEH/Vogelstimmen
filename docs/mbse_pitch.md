# MBSE Pitch — generische Folien (technisch / Showcase)

Der Mehrwert ist **nicht die Menge der Dokumente**, sondern dass ein **KI-Engineering-Assistent** Konsistenz, Durchgängigkeit und einen Digital Thread aufbaut — und dass das erstmals wirtschaftlich sinnvoll ist, weil bei richtiger Tool-Unterstützung kaum Mehraufwand entsteht.

Vollbild-Deck: [`../mbse/presentation.html`](../mbse/presentation.html) · Krones-Variante: [`mbse_pitch_krones.md`](mbse_pitch_krones.md)

---

## 1. Das Problem heute

Viele MBSE-Demos zeigen Ordner mit Dokumenten. Automotive/Bahn: 50–200 Artefakte — **Menge ≠ Qualität**. Änderungen brechen Traceability still und leise.

## 2. Die falsche Metrik

„Wir haben 27 Dokumente“ ist kein Erfolg. Erfolg = **jede Änderung ist nachverfolgbar und konsistent**.

## 3. Der neue Hebel: KI-Engineering-Assistent

Nicht Ersatz des Engineers — **Co-Pilot für Konsistenz**. Generiert und verknüpft: Req, SF, Architektur, Tests, Risiken, ADRs. IDs leben im **internen Modell**.

## 4. Live-Demo: Impact in 30 Sekunden

Requirement **E03 „Batterie ≥ 12 Monate“** → **18 Monate**.  
Graph: Architektur 🟡, PCB/Energie 🔴, Software 🟢, Tests ungültig 🔴.

[Demo starten](../mbse/index.html?demo=e03)

## 5. Digital Thread

SH → Req → UC → SF → Block → Interface → Test → Risiko → Dokument.  
Audit zeigt Lücken sofort. Export SysML v2 / JSON.

## 6. Warum jetzt wirtschaftlich?

Früher: Modellierungs-Overhead + manuelle RTM. Jetzt: KI erzeugt Entwürfe; Engineer **reviewt statt tippt**. Marginaler Mehraufwand ≈ 0, wenn das Modell Quelle der Wahrheit ist. Vogelstimmen = kleines Referenzprojekt, nicht Produkt.

## 7. Call to Action

Impact-Analyse öffnen · Export ansehen · dasselbe Prinzip auf eine Produktlinie übertragen.
